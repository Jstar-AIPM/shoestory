# 决策记录 · V2 输入方式与画面风格

> 记录时间：2026-09-22
> 背景：V1（只输型号 → 网上搜图 → 生成线稿）经真实验证后效果不达标，产品经理判断"问题不在绘画，而在**取材**"。
> 本文如实记录：**原方案 → 失败证据 → 判断转向 → 新方案 → 被撤回的方案**。每条结论都附实测数据。

---

## 一、输入方式：从「输入型号」改为「上传图片」

### 原方案（V1）
输入球鞋型号 → 文搜图 → 用搜到的图当参考 → 生成线稿。

### 失败证据（实测）
| 证据 | 数据 |
|---|---|
| 搜到的图角度不可控 | 文搜图返回的常是"两只鞋合影 / 3/4 角度 / 花背景"的资讯图 |
| **坏参考图会把结果带差** | 用坏参考图生成：质检 **0.605**；不用参考图、型号直出：**0.829**（Logo 可辨识 0.32 vs 0.90） |
| 结论 | "搜图"不是没帮助，而是**经常帮倒忙** |

### 新方案（V2）
**只支持上传图片**。用户从球鞋 App（得物/识货等）的商品详情页取"正测试图"（白底、正侧面、单只）上传。

### 为什么用户上传的图更可靠（实测）
用一张得物商品详情页截图跑通现有管线：
| 环节 | 结果 |
|---|---|
| 主体定位（详情页截图） | ✅ 自动框出鞋主体（宽高比 2.04） |
| 多主体判定（列表页截图） | ✅ 正确拒绝（列表页 5 个候选大小相近） |
| 去背景 + 3:2 白底归一化 | ✅ 复用现有代码，鞋身完整无破洞 |
| 耗时 | 截图 → 3:2 画布 = **1.15 秒** |

**判定规则（实测 3/3 正确）**：找"像鞋"的候选（宽高比 1.3–3.2）→ 只有 1 个则通过；多个但最大者 ≥ 次大者 2 倍则通过（其余视作缩略图）；否则拒绝并提示重传。

### 产品规则（明确）
1. **只接受**主体清晰、无争议、只有一双鞋的图片；
2. 列表页/多主体 → 提示"**无法识别主体**"并引导重传（文案要给出怎么做，不能只说失败）；
3. 引导文案提示：**点进商品详情页 → 长按保存原图**（截图会带 App 界面，原图更干净）；
4. 引导中可否点名得物/识货：**可以**（非商用、友好提示，产品经理确认）。

### 遗留问题
- 浅色/白色鞋的主体定位会漏（白色部分被当成背景白排除）→ **待修**；
- 拒绝阈值目前靠实测标定，样本仍偏少（1 正 2 负 + 6 张新截图）→ 继续扩充。

## 二、画面风格：从「纯白底」改为「浅牛皮纸底」

### 决定
- 底色：**浅牛皮纸**（约 `#F3EBD9`），带极轻纸纹；
- 线稿本体**不变**（仍为纯二值黑白线稿）；
- 实现层：**展示层换纸**（前端 + 导出时合成），**不改生成链路、不改质检闸门**。

### 依据
1. 前端主题本就叫「**纸白阅读**」（`card-paper`）——画稿与卡片应是同一种"纸"；
2. 纯白底 + 纯黑线对比过强，屏幕上看偏"刺眼"；纸色底更柔和、更有"纪念感"；
3. 实测：现有 AI 线稿换到牛皮纸底后观感明显提升（见 `本机素材目录/实验1-截图模式/13`、`14`）。

### 被撤回的方案
- **不做**"深色鞋填黑块"：产品经理指出——线稿要的是**轮廓与结构线**，黑鞋也是由不同分区组成；
  只有 **Logo** 需要填色。因此黑鞋与白鞋的线稿应当**几乎一致**。

## 三、Logo 填色：从「模型自由发挥」改为「显式识别 + 明确要求」

### 问题（实测发现）
| 鞋 | Logo 表现 | 实心块占比 |
|---|---|---|
| 白蓝 ASICS | ✅ 条纹填了实心黑 | 2.43% |
| **全黑 ASICS** | ❌ 条纹变成**空心轮廓** | 0.74% |

原因：黑鞋的 Logo 在照片里没有对比度，模型"看不见" → 不填。

### 新方案
```
视觉模型看图 → 输出「品牌 / Logo 形状 / 位置 / 占比」
   ├─ 注入生图提示词：「把 ASICS 交叉条纹用实心黑填充，其余保持线稿」
   └─ 同时用于「归档标题自动命名」
```
- 关于「必要时联网搜」：**默认不做**。视觉模型看图即可识别（更准、更快、更省开销，约 /次）；
  搜索仅作冷门品牌的兜底（本机计算），平时不触发。

### 配套的填色规则（写进提示词 + 纳入质检）
- **允许填实**：Logo、鞋眼孔、透气孔等小元素；
- **不得填实**：鞋带、中底、鞋面（一律用轮廓线/结构线表达）。
- 反例：全黑鞋的鞋带曾被画成实心黑块 → 需要新增 `laces_solid_ratio` 类检查。

## 四、生成过程：加入「生成感」动效

### 决定（档 2 + 草稿预览）
```
用户点「开始画」
  ↓ 约 1 秒：先用纯 CV 出**草稿**（已实测 1.15 秒，）
  → 「扫过式揭示」动效把它画出来（移动软边遮罩 + 一道扫光，纯 CSS 可实现）
  ↓ 后台同时跑 AI（30–60 秒，）
  → 正式稿完成时**淡入替换**草稿（视觉上像"精修完成"）
```

### 依据
- 产品经理要求"生成过程要有动态感、生成感，像加载动效"；
- 我们已有真实阶段标签与百分比（型号校对/找参考图/去背景/生成线稿/后处理/质检），
  动效是在真实事件上做视觉，**不是假进度条**；
- 用 CV 草稿把"等待"变成"过程"，直接解决 30–60 秒等待的体验短板。

### 备选与取舍
| 档 | 做法 | 复杂度 |
|---|---|---|
| 1 | 阶段标签 + 呼吸/流光 | 低（半天） |
| **2（选定）** | **扫过式揭示**（遮罩 + 扫光） | 中（1–2 天） |
| 3 | 真·逐笔绘制（需轮廓转 SVG + 排笔顺） | 高（3–5 天），后续可选 |

## 七、Logo 与文字：三档规则（产品经理补充，2026-09-22）

### 规则
| 档 | 内容 | 处理方式 | 是否硬性 |
|---|---|---|---|
| **① 标志性图形** | Nike 勾、adidas 三道杠、ASICS 线条、Jumpman、New Balance「N」等 | **实心填色** | ✅ 硬性（缺了就是错的） |
| **② 字母与文字** | 「AIR」「ZOOM」「Air Force」等鞋身字样 | **渲染出可辨认的字母** | ⚠️ 尽量（能识别就还原） |
| **③ 识别不到时** | — | 允许不显示，但不显示不如显示 | 可接受降级 |

### 技术判断（诚实记录风险）
- ① 可靠：图形填色是图像模型的强项（已实测白蓝 ASICS 条纹填色正确）。
- ② **风险最高**：图像模型**渲染小字不可靠**（长串文字尤其容易糊/写错）。
  → 采用**两级策略**：
  1. **先让模型画**（提示词里明确写出要呈现的字母，如「鞋侧写出 AIR 三字母」）；
  2. **质检发现缺失/乱码 → 兜底**：把原图对应文字区域裁出来、矢量化后**贴合到线稿**（确定性做法，可保证还原）。
- **原则：宁缺勿错**。写错的字母比不写更伤"纪念档案"的可信度 —— 长串文字若无法保证正确，宁可省略或只保留主字母。

### 质检新增项
- `logo_filled`（硬性）：标志性图形必须填实；
- `laces_solid_ratio`（硬性上限）：鞋带不得被填成实心块；
- `text_legible`（软性）：文字可辨度 —— 不达标只触发"兜底贴合"，不决定成败。

## 八、上传后先裁切 + 非鞋保险（产品经理补充，2026-09-22）

### 8.1 手动裁切框（替代"只靠文案引导"）
```
上传图片 → 自动给出「建议裁切框」→ 用户可拖拽微调 → 确认 → 进入生成
```
- 产品经理判断：**比纯文字引导更直接**（"就像微信上传头像那样拖一下"），
  且能一次性消除列表页/多主体/带 App 界面等问题；
- 自动建议框仍然保留（用户不调也能用），做到"**自动 + 可改**"；
- 移动端要求：整框可拖 + 四角把手热区放大（手指精度考虑）。

### 8.2 非鞋主体保险机制
- 目的：用户传了杯子/手机等**明显不是鞋**的图时，明确告知"这个工具只画鞋"，而不是硬画出一堆怪线；
- **与品牌/型号识别合并为一次视觉调用**（少一次调用与延迟），返回：
  `是否鞋 · 是否只有一只 · 品牌 · 型号 · Logo 类型与位置 · 鞋身文字清单`
- **三档判定**（避免误拒）：
  | 情形 | 处理 |
  |---|---|
  | 明确是鞋 | 通过 |
  | **明确不是鞋**（高置信） | 拒绝 + 友好提示 + 告诉他该传什么 |
  | 不确定（低置信） | **放行 + 软提示**（"如果不准，换一张侧面图"）—— 拒绝太严比选错更伤体验 |

### 8.3 提示文案（草案，待确认）
- 明确不是鞋：`看起来这张图里不是运动鞋 —— 我看到的更像「马克杯」。这个工具专门把球鞋画成黑白线稿，所以这次先不画了。你可以上传一张球鞋的侧面图（白底商品图最好），我马上就能画。`
- 框选里有多只鞋：`这个框里有好几双鞋，我不确定你想画哪一双。把框拖到只包住你要的那一双，就好了。`
- 不确定是不是鞋：`我不太确定这是不是一双球鞋 —— 先按你说的画。如果结果不对，换一张更清晰的侧面图会好很多。`

### 8.4 成本
合并为一次视觉调用：约 **/双**（原先"预筛 + 命名"两次调用，合并后更省）。

## 九、更新后的完整流程（V2 定版）

```
① 上传（拖拽 / ⌘V 粘贴 / 相册）
② 自动建议裁切框 → 用户可拖拽微调 → 确认
③ 一次视觉调用：是否鞋 · 是否单只 · 品牌/型号 · Logo 类型与位置 · 文字清单   ()
④ 判定：非鞋→友好拒绝；框内多只→提示重新框选；是鞋→通过
⑤ 去背景 + 3:2 白底归一化（复用现有，1.15 秒）
⑥ 生成线稿：提示词注入 Logo 填色要求 + 文字清单        ()
⑦ 质检：logo_filled（硬）· laces_solid_ratio（硬）· text_legible（软）
   → 不合格自动重画一次（不额外扣用户额度）
⑧ 文字兜底：若文字缺失/乱码 → 从原图裁文字区域贴合到线稿
⑨ 展示层：浅牛皮纸底 + 动效（1 秒 CV 草稿 → 扫过式揭示 → AI 稿淡入替换）
⑩ 归档（标题用第③步识别的品牌+型号自动填）
```
